🚨 Common Gotchas

The "Off by One Day" Bug

Parsing "2024-06-15" (date-only, no time) is treated as UTC midnight. If you are in UTC-5, that becomes June 14th at 7pm local time.

Fix: For date-only values, either keep them as strings or parse with "2024-06-15T00:00:00" (no Z) so it is interpreted as local.

Comparing Dates Across Timezones

Two dates that look different can be the same instant: "2024-06-15T14:30:00Z" and "2024-06-15T10:30:00-04:00" have the same timestamp.

Fix: Always compare timestamps (.getTime()), never string representations.

DST Transitions

Adding "24 hours" is not always "one day." When DST changes, a day can be 23 or 25 hours. Similarly, some times simply do not exist (e.g., 2:30 AM during spring forward).

Fix: Use calendar arithmetic (add 1 to the day), not millisecond arithmetic. The Temporal API (Stage 3) will solve this properly.
